# 平台实测记录

本文件记录两个平台的**入口、参数、字段结构与判据**，全部来自实际复核。
只写方法与判据，不含任何联系方式；入口地址写在代码里，便于随站点改版维护。

实测复核日期：2026-10（含此前一个月的多轮验证）

---

## 一、中国政府采购网（政府采购体系）

### 1.1 入口

官方检索是**独立的参数化接口**，不是浏览器地址栏里的目录页
（那些目录页多为前端 JS 渲染，直接请求拿不到数据）。

关键路径段：`/bxsearch`（详见 `src/tender_notice_cn/ccgp.py` 的 `SEARCH_URL`）。

### 1.2 参数（实测）

| 参数 | 作用 | 实测结论 |
|---|---|---|
| `searchtype=1` | 固定值 | — |
| `page_index` | 页码，从 1 起 | ✅ **翻页真实生效** |
| `dbselect=bidx` | 检索招标公告 | — |
| `pinMu` | 品目：0 不限／1 货物／2 工程／3 服务 | 可用 |
| `bidType` | 公告类型，0 为不限 | 可用 |
| `kw` | 标题关键词 | 可用 |
| `start_time` / `end_time` | `YYYY:MM:DD` | ✅ **服务端真实生效** |
| `timeType=6` | 使用自定义起止日期 | ✅ **必填**，否则日期被忽略 |

### 1.3 字段结构（⚠️ 最容易写错的地方）

已抓真实页面核实：

```html
<div class="vT-srch-result-list-bid">
  <li>
    <a href=".../t20261003_27439571.htm">标题</a>
    <p></p>
    <span>2026.10.03 12:04:38 | 采购人：XXX | 代理机构：YYY
          <br/><strong>更正公告</strong> | | <strong>（地区，常空）</strong>
    </span>
  </li>
</div>
```

**常见误写的结构注释**：「时间 | 采购人 | 代理机构 编号 | 地区 | 类别」。**这是错的**：

| 项 | 误写的假设 | 真实情况 |
|---|---|---|
| 编号 | 有该字段 | **根本没有** |
| 第 4 段 | 地区 | **公告类型** |
| 第 5 段 | 类别 | 地区（省份简称，**经常为空**） |
| 公告类型 | 第 5 段 | 在 `<strong>` 标签内 |

**后果**：按分隔段位置序号取数会产出**错位字段** ——
"地区"列里装"公开招标公告"，且**不会报错**。
不逐条抽查根本发现不了，而按地区筛客户项目时会全错。

**正确做法**：`<li>` 内取 `<a>`（标题/链接）与 `<strong>`（类型/地区），
文本按中文标记（`采购人：`／`代理机构：`）与时间正则提取，
**不依赖分隔段的位置序号**。

注意 `<br/>` 不产生分隔符，会导致"公告类型"或"地区"粘在"代理机构"尾部，需后处理剥离。

### 1.4 限流特征

- 被拦时返回 **HTTP 200** + 约 2.9 KB 的拦截页（**不是 403**），
  所以**不能只看状态码**，必须检查正文特征。
- 限流是**短时**的：被拦后等待**约 60 秒**即恢复。
- 请求间隔 6~10 秒可长时间稳定采集（实测连续 100 页无中断）。

### 1.5 编码

HTTP 响应头**不带 charset**，页面 meta 声明 utf-8。
直接用 `resp.text` 会回落到 ISO-8859-1 → 中文乱码 →
**且"频繁访问"关键词匹配会静默失效**（不报错、只给空结果）。
必须显式按 utf-8 解码。

## 二、中国招标投标公共服务平台（依法必须招标项目）

### 2.1 入口

门户主站下的信息公开检索接口，返回 **JSON**：

```json
{"success": true, "object": {"returnlist": [...], "page": {...}}}
```

（该路径不受另一子域的路径级 WAF 拦截 —— 主站与子域的规则不同，
这是排查时容易漏掉的一点。）

### 2.2 请求要求

必须带齐：`Referer`、`Origin`、`X-Requested-With`、`Content-Type`。缺任一项会被拒。

### 2.3 三条硬约束（不可绕过）

**① 翻页不可用**

`pageNo >= 2` 一律返回验证码校验失败（`v-token` 为空）。
**本库不逆向、不绕过验证码**，改用 `row` 放大单页容量。

**② `row` 可放到 500**

实测 `row=500` 正常返回 500 条（此时全库 `totalCount` 约 78 万）。
这是突破"单页 15 条"限制的正当办法。

**③ 日期与地区筛选无效**

| 参数 | 是否生效 |
|---|---|
| `searchName`（关键词） | ✅ 生效 |
| `searchIndustry`（行业分类） | ✅ 生效 |
| `searchArea`（地区） | ❌ 服务端忽略 |
| `searchTimeStart` / `searchTimeStop` | ❌ 服务端忽略 |
| `timeTypeParam` | ❌ 服务端忽略 |
| `bulletinIssnTime` | ❌ 一提交即返回 0 条 |

**因此分片维度只能是"关键词／行业"，时间窗必须本地筛。**

### 2.4 返回字段（实测字段名）

| 字段 | 含义 | 注意 |
|---|---|---|
| `businessObjectName` | 公告标题 | |
| `industriesType` | 所属专业 | |
| `regionName` | 所属区域 | 多为「省+市」 |
| `transactionPlatfName` | 所属交易平台 | |
| `receiveTime` | **接收时间** | 含**提前发布/预告**，会晚于当天 |
| `bulletinEndTime` | 公告结束时间 | ⚠️ 存在 `1970-01-01` 空值占位 |
| `tenderProjectCode` | 项目代码 | |
| `businessId` | 业务 ID | 拼详情链接用 |

### 2.5 口径边界（必须写进交付物）

因日期筛选无效，采集只能做「关键词分片 × 全库 → **本地**按接收时间筛」。
产出的**不是"某时段全量"，而是"该时段内命中关键词的子集"**。

另外 `receiveTime` 含提前发布与预告 —— 实测出现过接收时间晚于检索日 **27 天**的记录。
这类项目尚未正式发布，**投标前须回源站确认公告状态**。

## 四、跨平台通用的两个坑

### 4.1 系统代理（最隐蔽，曾导致整轮排查方向错误）

本机若开启系统代理并写入 **Windows 注册表**（Internet 设置），
`requests` 会通过 `urllib.request.getproxies()` **自动读取它**：

```python
import urllib.request
urllib.request.getproxies()
# 可能返回 {'http': 'http://127.0.0.1:xxxx', ...}
```

- **仅 `unset http_proxy` 环境变量摘不掉它** —— 环境变量已清空，注册表仍在。
- 若该代理出口被目标站点风控标记，表现为"**永远**拿到拦截页"，
  极易被误判为"本机 IP 被封"，从而在"怎么绕限流"上反复试错。
- **处置**：`session.trust_env = False` + `session.proxies = {}`（本库默认）。
  浏览器自动化则用"不启用代理"的启动参数。

**排查纪律**：抓不到数据时，**先确认请求实际走了哪条网络路径，再怀疑目标站点。**

### 4.2 失败要分类，不要一律重试

实测教训：曾把瞬时 `Read timed out` 与"被限流"同等对待；
更早的版本甚至把非限流错误直接放弃 —— 结果采集在第 7 页就中断。

三类必须分开：

| 类型 | 特征 | 处置 |
|---|---|---|
| 限流 | 返回拦截页 / `success=false` | 长退避（约 90 秒）后重试，次数有限 |
| 网络抖动 | 超时、连接中断 | 短退避重试（3/6/9 秒） |
| 结构变更 | 找不到结果容器 | **不重试**（重试也不会变），直接报错并提示更新选择器 |

## 五、数据真伪校验清单（每次采集后必做）

1. **唯一标题数 = 总行数**（去重后不应有重复）
2. **重复次数不得 ≈ 页数** —— 这是假翻页的指纹
3. **表头/提示行不得混入**
4. **端点日期逻辑校验**：非日期格式、或"截止早于发布"的值一律置空
5. **字段结构抽查**：抽 3~5 条目视核对，确认没有错位
   （例如"地区"列里不应出现"公开招标公告"）

# 合规立场与使用边界

本文件说明本工具**做什么、不做什么**，以及使用者需要注意的边界。
这些不是免责套话，而是设计约束 —— 代码里对应用户可见的行为。

---

## 一、只采集公开信息

- 只访问**无需登录**即可查看的公开页面与公开检索接口。
- 不获取、不使用任何非公开信息（例如评标内部情况、他人投标文件）。
- 不采集个人信息；采集范围限于**招标公告本身**的公开字段
  （项目名称、采购人、代理机构、地区、公告类型、时间等）。

## 二、不绕过访问控制

**这是本项目的硬约束，写在代码里。**

- 遇到验证码、登录墙、签名校验等访问控制 —— **降速、等待，或改用人工。**
  例如公共服务平台的翻页请求要求验证码 token，
  本库的选择是**放弃翻页**，改用 `row=500` + 关键词分片这一正当方式扩大覆盖。
- **不逆向**站点风控参数，不构造伪造签名，不模拟已登录会话。
- 本库提供的 `--use-proxy` 仅为**正常网络出口切换**（例如用户本来就在代理环境内），
  不为绕过风控而设计。

## 三、控制访问频率

- 默认请求间隔保守（政采网 6~10 秒，公共服务平台约 1.5 秒/分片）。
- 被限流时**长退避后有限次重试**，而不是加速重试。
- 请勿把间隔调至过低。若你需要长期、大批量采集，
  **建议对接合规的数据服务**，而不是硬扛官网风控。
- 测试套件**全部离线运行**（使用内置样例页），
  这样 CI 稳定，也不会给对方站点造成任何压力 —— 这是刻意的设计选择。

## 四、不承诺能力边界之外的事

- **不承诺"自动全网抓取"**。本库只覆盖两个全国级渠道。
  省市平台、行业平台、国企采购平台均未覆盖，它们在文档中**如实标注为未覆盖**，
  而不是用"暂不支持"含糊带过。
- 各站点的公开深度不同；能拿到什么字段，在 README 的对照表中逐项列出，
  不夸大。

## 五、输出的是线索，不是结论

- 采集结果**必须回源站复核**。平台数据存在延迟、遗漏与转载失真。
- 候选池的"总判定"一律为 `待确认` ——
  资格核验需要投标方自身的主体资格／资质／业绩／信用材料，
  **在拿到这些材料前，任何一条都不得判为合格**。
- 本工具不提供投标决策建议，也不做法律定性。

## 六、不提供规避性功能

本库**不提供**、也不接受以下方向的扩展：

- 规避招标文件规则、规避评审程序；
- 影响或干扰其他投标人；
- 任何形式的材料造假。

## 七、使用者责任

- 使用本工具采集与使用数据，须自行确认符合目标站点的使用条款
  以及适用的法律法规。
- 若目标站点明确声明禁止自动化访问，请遵守其要求。
- 采集结果用于商业决策前，请自行核验。

## 附：数据字段的处理原则

| 原则 | 代码中的体现 |
|---|---|
| 取不到就留空，**绝不猜** | 接口/页面未提供的字段写"需点入详情确认"，不填推断值 |
| 冲突值全部列出，不任选其一 | 日期等字段做逻辑校验，异常值置空**并标注原因**（`issues` 列） |
| 不静默修补 | 检出翻页失效等质量问题时**报警并停止**，不悄悄去重后当成功 |
| 口径必须显式声明 | 日志与 Markdown 产物中打印"是子集不是全量"等边界说明 |

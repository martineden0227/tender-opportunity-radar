# tender-notice-cn

中国招标公告采集工具。覆盖两个**全国级**公开渠道：

| 渠道 | 体系 | 采集入口形态 |
|---|---|---|
| **中国政府采购网** | 政府采购 | 参数化检索接口（HTML） |
| **中国招标投标公共服务平台** | 依法必须招标项目 | 信息公开检索接口（JSON） |

输出统一为一张 **13 列的项目候选池**，可直接用于投标项目筛选。

---

## 为什么值得用这个，而不是随手写个爬虫

因为招标公告站点的"坑"大多**不会报错**，只会静默给你错数据。本仓库把实测踩过的
坑全部固化成了代码与测试：

| 坑 | 症状 | 本仓库的处置 |
|---|---|---|
| **翻页失效** | 程序报"6 页 96 条"，实际只有 **15 个唯一标题**，每条重复 6 次 | `check_paging_integrity()` 检出并报警，**不拿重复数据充数** |
| **字段错位** | 按分隔符位置取数，"地区"列里装的是"公开招标公告" | 按标签与中文标记定位，附回归测试 |
| **脏日期** | `截止=2025-10-10` 而 `发布=2026-09-30`（早一年），**不报错** | `clean_date()` 做格式与逻辑双重校验，不合格即置空 |
| **编码猜错** | 中文变乱码，**关键词匹配静默失效**，只给空结果 | 按 HTTP 头→meta→utf-8→gbk 逐级解码，检测替换字符 |
| **系统代理** | 请求被导向本机代理，**永远**拿到拦截页，极易误判为"IP 被封" | 默认直连（`trust_env=False`），附排查方法 |
| **限流误判** | 拦截页返回 **HTTP 200** 而非 403，只看状态码会漏检 | 按正文特征识别，且区分"限流／网络抖动／结构变更"三类分别退避 |
| **表头混入** | 结果里出现标题为"招标公告名称"的假记录 | `is_junk()` 过滤 |
| **跨分片重复** | 关键词分片时同一公告多次命中，被误判为翻页失效 | 两者口径分开，不混用判据 |

## 安装

```bash
git clone https://github.com/<your-account>/tender-notice-cn.git
cd tender-notice-cn
pip install -e .
```

依赖仅 `requests` + `beautifulsoup4`。

## 快速开始

```bash
# 0) 先做连通性自检（一次请求内判断：能采 / 被限流 / 结构变了）
tender-notice check all

# 1) 采集中国政府采购网（该平台日期筛选在服务端真实生效）
tender-notice ccgp --days 3 --pages 5 --output ccgp_notices.csv

# 2) 采集中国招标投标公共服务平台（该平台日期筛选无效，时间窗在本地筛）
tender-notice ceb --days 3 --output ceb_notices.csv

# 3) 合并为项目候选池
tender-notice merge ccgp_notices.csv ceb_notices.csv \
  --window "近三天" --output project_pool.csv --markdown project_pool.md

# 4) 离线演练（不联网，验证解析链路；CI 也跑这个）
tender-notice demo
```

作为库使用：

```python
from tender_notice_cn import ccgp, ceb, pool

a = ccgp.collect(pages=3, start_time="2026:10:01", end_time="2026:10:03")
b = ceb.collect(start="2026-10-01", stop="2026-10-03", keywords=["电梯", "园林绿化"])

rows, stats = pool.merge(a + b, log=lambda *_: None)
pool.write_csv(rows, "project_pool.csv")
```

## 两个平台的实测差异（决定怎么用）

| 维度 | 中国政府采购网 | 中国招标投标公共服务平台 |
|---|---|---|
| 日期筛选 | ✅ **服务端真实生效** | ❌ 服务端忽略，需本地按接收时间筛 |
| 翻页 | ✅ 真实生效（参数化页码） | ❌ **不可用**（需验证码 token） |
| 单次容量 | 固定每页约 20 条 | **`row=500`**（本库默认拉满） |
| 发布时间 | 精确到秒 | 仅日期，且含**提前发布/预告** |
| 采购人／代理机构 | ✅ 列表页即完整 | ❌ 需点入详情 |
| 公告类型 | ✅ 有 | ⚠️ 列表页不含 |
| 详情链接 | ✅ 可直接打开 | ⚠️ 需用业务 ID 拼接 |
| 地区 | ⚠️ 部分行缺失 | ✅ 有 |
| 限流特征 | HTTP **200** + 约 2.9 KB 拦截页 | 返回 `success=false` + 提示信息 |

**由此引出一条必须理解的口径差异**：

- 政采网取到的是「**该时段的全量命中**」；
- 公共服务平台因日期筛选无效，只能做「**关键词分片 × 单页大容量 → 本地按接收时间筛**」，
  取到的是「**该时段内命中关键词的子集**」，**不是全量**。

> 本库在日志与 Markdown 产物中都会显式打印这条边界，避免使用者误以为拿到了全量。

## 输出字段（候选池 13 列）

| 列 | 说明 |
|---|---|
| 序号 | 连续编号 |
| 成熟度 | `机会级`（招标公告） |
| 项目名称 | 公告标题 |
| 标段／招标内容 | 列表页不提供 → 标注"需点入详情确认"，**不编造** |
| 采购人／代理机构 | 合并为一栏 |
| 区域 | 实施地 |
| 预算·限价 | 列表页不提供 → 同上 |
| 投标截止 | 列表页无该字段时写"以平台日程安排为准"（**字段级说明，不是缺件**） |
| 总判定 | 一律 `待确认` —— 见下方"资格核验"说明 |
| 来源平台 | `全国级·<平台名>` |
| 详情入口 | 源站复核入口 |
| 检索日期 | 结论可复现的依据 |
| 备注 | 发布时间／公告类型／所属专业／项目代码／数据质量标注 |

**字段只减不增**：想记的附加信息写进「备注」，不新增列。

### 关于「总判定 = 待确认」

资格核验需要投标方自身的**主体资格／资质／业绩／信用**四类材料。
在拿到这些材料之前，**任何一条都不得判为合格** ——
用默认值或行业经验把它填成"符合"，是这个环节最严重的错误。

本工具负责"把信息抓进来"，不负责"这条能不能投"。

## 已知限制（如实列出，不要指望它做不到的事）

1. **不承诺"自动全网抓取"**。多数交易平台有 WAF／验证码／登录墙，
   本库只覆盖上述两个全国级渠道；省市平台、行业平台（电网、铁路、通信、
   医药、军队、烟草）、国企阳光采购平台均**未覆盖**。
2. **公共服务平台的翻页不可用**。该站点翻页请求要求验证码 token，
   **本库不逆向、不绕过验证码**，改用 `row=500` + 关键词分片的正当方式扩大覆盖。
   因此覆盖面受限于关键词表 —— 词表越贴合业务范围，覆盖越准。
3. **中标类公告默认被过滤**（中标／成交／候选人／废标／终止）。
   这类信息属"研究竞争对手"范畴，需要时加 `--keep-results`。
4. **不解析招标文件正文**。列表页只有标题级信息，预算、标段、资格要求
   都需点入详情或下载招标文件后才能获得。
5. **采集结果必须回源站复核**。平台数据存在延迟、遗漏与转载失真，
   本工具输出的是**线索与入口**，不是结论依据。

## 抓不到数据怎么办（按这个顺序排查）

1. **先确认网络路径**——这是最容易被忽略、也最像"目标站点封了我"的一步：

   ```bash
   python -c "import urllib.request; print(urllib.request.getproxies())"
   ```

   若返回了代理地址，说明本机开了系统代理（常见于 Windows 注册表 Internet 设置）。
   `requests` 会**自动读取**它，**仅 `unset http_proxy` 环境变量摘不掉**。
   本库默认直连；若你确实需要走代理，加 `--use-proxy`。

2. **跑自检定位**：`tender-notice check all`
   - `blocked` → 被限流。**等约 60 秒**通常即恢复；调大 `--delay`（如 `8-14`）可稳定跑更久。
   - `network` → 网络不通，检查连通性与代理。
   - `structure` → 站点页面结构可能已变更，需更新选择器。

3. **不要靠"加重试/换 UA"硬扛**。先分清是"限流"还是"网络抖动"还是"结构变了"——
   三者处置完全不同，混为一谈会白费很多轮。

## 合规与使用边界

- 只采集**公开**信息；不获取、不使用任何非公开信息。
- **不绕过**验证码、登录墙等访问控制。遇到风控即降速、等待或改用人工。
- 请求间隔默认保守（政采网 6~10 秒）；**请勿调至过低**。
- 长期、大批量采集建议对接合规的数据服务，而不是硬扛官网风控。
- 采集结果的使用须自行确认符合目标站点的条款与相关法律规定。

本工具**不提供**任何规避规则、规避评审或影响他人投标的功能。

pip install -e ".[dev]"
